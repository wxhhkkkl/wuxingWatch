# Phase 0 Research: 四柱精髓旺度法强弱喜忌 + 刑冲合害条件入命盘图

**Feature**: `008-yongshen-steps` | **Date**: 2026-08-16
**算法依据全文**: [algorithm-reference.md](algorithm-reference.md)（从 `doc/四柱精髓（许心友）.doc` 逐章提炼，含全部数值表与 10 个验收命例）

## R1: 静态旺度计算口径

- **Decision**: 按书中度数体系实现——1 天干=1 度；藏干余气 1/中气 2/半本气 3/本气 4/纯本气 5；四墓库藏干随月令取特殊表；通根按距离递减（同柱 0 / 相邻 0.5 / 相隔 1 / 远隔 2，月令通根视同柱，连片不减）；五行静态旺度 =（天干 + 通根藏干和）× 月令状态系数（旺 2 / 余气 1.6 / 相 1.5 / 休 0.8 / 囚 0.7 / 死 0.5）；月令被合化时取双状态平均。
- **Rationale**: 书中 p8-18 给出完整数值与多道验算例题，可直接编程；`hidden_stems.wang_xiang()` 已有旺相休囚死可复用。
- **Alternatives**: 继续沿用 005 的 544 分标准化体系（被否——用户明确更换方法）；简化计数法（被否——不准确正是本次动因）。

## R2: 动态修正 = 生克增减力 + 刑冲合害（带成立条件与先后顺序）

- **Decision**: 静态旺度之后，按 algorithm-reference §2（生克增减力 ×0.7/×1.3 等、生克权阈值 2.4）、§3-8（五合/六合/三合/三会/半合/六冲/三刑/自刑/六害的成立条件与增减力数值）、§9（论处先后顺序：天合地合→天克地冲→…→六害，含合冲并见与并存规则）依次修正，得最终旺度。
- **Rationale**: 这是该书区别于静态评分法的核心（"五行最后的旺度"），spec FR-003~005 直接对应。
- **Alternatives**: 只实现合冲不实现刑害（被否——spec 要求完整条件）；沿用 005 的 ×1.05/×1.15 粗修正（被否——口径不同）。

## R3: 格局判定阈值

- **Decision**: 日主最终旺度对照分类表（弱极 0~0.8 / 太弱 0.8~2.4 / … / 太旺 26~36 / 旺极 ≥36）。正格：能独立且一般 4.0~20.0；从弱：<2.4 且无实质帮扶/无根（被合绊刑冲掉的根视为无根）；从强：≥26 且克泄耗方全部太弱不能独立；化格：日干参与的五合合化成功。
- **Rationale**: 书中 §11 明确阈值与"能独立=有生克权"的判别；10 号命例提供 4 个锚点（旺极 36/38 从强、1.6 从弱、3.0 正格）。
- **Alternatives**: 005 的 7 级映射（被否——随旧法下线）。

## R4: 取用神 = 格局用神 + 调候用神 双输出

- **Decision**: 格局用神按书中流程：量日干旺度→辨格局→结合日干五行之性，一般只考虑月干/时干/日支三个位置；正格扶抑、从格从势、化格从化神。调候用神按逐月调候需求表取（正月火、四五六月水或湿土、九月水、十~十二月火或燥土等）。两者并列输出，各附依据。
- **Rationale**: spec clarify Q2 用户选择"双用神并列"。
- **Alternatives**: 单用神+调候附注（用户未选）；调候优先（用户未选）。

## R5: 大运介入旺度步的实现机制

- **Decision**: predict 响应中**预计算每个大运的介入修正**（`xi_yong.wangdu.dayun_adjustments[]`，每大运一项：运支状态增减 + 运干同类/通根叠加 + 运支与原局刑冲合害修正 → 各五行大运旺度与日主新等级）。前端展示"大运介入"步时按当前选中大运取对应项，切换大运本地换数据、不再请求。喜忌结论不随大运变。
- **Rationale**: 大运列表在排盘时已确定（≤10 步），纯函数毫秒级；避免新增端点与额外交互往返；符合 spec"切换当前大运时该步随之更新"。
- **Alternatives**: 新增 POST /api/charts/wangdu 端点按需计算（被否——多一次往返，无必要）；前端本地实现大运旺度（被否——引擎在后端，前端重实现增加口径漂移面）。

以下为书中"活看/自悟"处的固定裁定，保证可重复计算（spec SC-002）。**如有异议以用户最终确认为准**：

## R7: 命盘图关系判定改造——前端实现 + 对拍测试

- **Decision**: 维持 007 既定架构（关系判定纯前端），在 `frontend/src/utils/relations.ts` 重写 `buildRelationPairs` 为条件判定：相邻才论（地支中隔须为其中一支本身；天干中隔为同类可论生克不论合）、五合合化/合绊/争合、地支各关系成立条件、§9 先后顺序裁定、大运流年按"岁运介入"规则参与。返回结构扩展为 `{ established: RelPair[], rejected: { pair, reason }[] }`；连线只用 established，汇总区新增"未成立"分组。**与后端口径一致性通过对拍测试保证**：共享书中命例 + 构造盘（隔位合、争合、合冲并见）作为前后端共同测试基准。

- **Alternatives**: 后端输出判定结果（被否——改 007 纯前端契约，且大运/流年切换需再请求或预计算组合爆炸）。

## 验收基准

- **引擎正确性**: algorithm-reference §13 的 10 个命例作为 pytest 锚点（静态旺度逐行断言 + 大运旺度 + 格局/用神结论），覆盖 spec SC-001（≥5 例 100% 一致）。
- **可复现性**: 同一输入两次计算深度相等（SC-002）。
- **前后端口径对拍**: 构造盘（隔位合/争合/合冲并见/主冲被绊）的关系判定结果前后端一致（SC-004/005）。
