# Feature Specification: 移动端八字排盘工具（Mobile BaZi Chart Tool）

**Feature Branch**: `001-bazi-mobile-tool`  
**Created**: 2026-08-08  
**Status**: Draft  
**Input**: User description: "我要做一个手机上能使用的八字工具，用户输入自己的出生时间、地点、姓名，男女，进行排盘；需要包含八字、流年大运、人元司令、胎元、命宫、身宫等等信息；通过这些信息给出当前八字的喜忌；用户可以用手机号进行登陆，存储自己查过的八字信息；"

## Clarifications

### Session 2026-08-08

- Q: 是否支持为他人（家人）排盘并保存？ → A: B（本人 + 家人，记录可标注人物与关系，默认"本人"）
- Q: 排盘结果是否需要分享/导出功能？ → A: B（生成命盘图片，可保存相册/分享社交渠道）
- Q: 流年（岁运）默认展示范围？ → A: C（当前流年 + 未来 10 年）
- Q: 喜忌（用神/忌神）分析的呈现深度？ → A: C（结论 + 分析依据 + 详细解读：十神、事业/财运/健康方向）
- Q: 排盘结果生成的目标速度？ → A: C（点击排盘后 5 秒内展示完整结果）
- Q: 出生日期时间是否需要支持农历输入？ → A: B（公历/农历可切换，农历自动换算为公历后排盘）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在线排盘（核心功能）(Priority: P1)

用户输入自己的姓名、性别、出生日期时间、出生地点，系统立即完成排盘并展示完整命盘：八字四柱（年柱、月柱、日柱、时柱的天干地支与五行）、大运（起运岁数与各步大运）、流年、人元司令、胎元、命宫、身宫，以及基于命局分析的喜忌结论（用神、喜神、忌神）、分析依据与简要命理解读（十神、事业/财运/健康方向）。

**Why this priority**: 排盘是产品的核心价值所在，用户最迫切的需求就是快速得到一份准确的命盘。没有排盘功能，登录与保存记录都无从谈起，因此这是必须最先交付、可独立上线的能力。

**Independent Test**: 输入同一组出生信息（如 1990-05-20 10:30、北京市、男），系统输出包含四柱、大运、流年、人元司令、胎元、命宫、身宫、喜忌的完整结果，可独立验证且无需登录。

**Acceptance Scenarios**:

1. **Given** 用户进入排盘页并填写姓名、性别、出生日期时间、出生地点，**When** 用户点击"开始排盘"，**Then** 系统展示完整命盘，包含年、月、日、时四个柱的天干地支与五行属性
2. **Given** 用户填写了出生地点，**When** 系统执行排盘，**Then** 系统依据该地点的真太阳时排盘，并在结果中展示实际采用的时间
3. **Given** 排盘结果已生成，**When** 用户浏览结果页，**Then** 能分别查看大运（含起运岁数）、流年、人元司令、胎元、命宫、身宫等信息
4. **Given** 排盘结果已生成，**When** 用户查看"喜忌分析"部分，**Then** 能看到用神、喜神、忌神、"宜补五行 X、忌五行 Y"的通俗说明、分析依据（日主强弱、五行旺衰、用神取法），以及事业/财运/健康方向的方向性解读
5. **Given** 用户切换到农历输入并选择农历生日，**When** 系统执行排盘，**Then** 系统将农历正确换算为公历后排盘，并在结果中同时展示农历与公历日期

---

### User Story 2 - 手机号登录 (Priority: P2)

用户使用中国大陆手机号接收短信验证码完成注册与登录。登录态在应用内保持，用户无需每次重复验证。未登录用户仍可使用排盘功能，仅在涉及保存时被引导登录。

**Why this priority**: 登录是"存储自己查过的八字信息"的前提，属于账户体系的基础能力。核心排盘可独立交付，登录紧随其后。

**Independent Test**: 使用一个有效手机号完成验证码注册、登录、退出、再次登录全流程，可独立验证。

**Acceptance Scenarios**:

1. **Given** 用户输入有效的 11 位手机号并点击"获取验证码"，**When** 系统发送验证码且用户输入正确的验证码，**Then** 用户登录成功并进入应用
2. **Given** 用户首次使用该手机号登录，**When** 验证通过，**Then** 系统自动创建账户并进入登录态（注册与登录合一）
3. **Given** 用户输入错误的验证码，**When** 用户提交，**Then** 系统提示验证码错误且不进入登录态
4. **Given** 用户已完成登录并关闭应用，**When** 用户再次打开，**Then** 无需重新输入验证码，保持登录状态

---

### User Story 3 - 保存排盘记录 (Priority: P2)

已登录用户可将当前排盘结果（本人或家人）保存到自己的账户下，每条记录可标注对应人物与关系（本人/子女/父母/其他，默认"本人"），并可附加备注。保存后用户随时可找回完整排盘结果。

**Why this priority**: 保存记录是用户明确提出的核心诉求之一，与登录配套形成"查过就能再找到"的价值闭环。

**Independent Test**: 登录用户完成一次排盘并保存，随后在记录列表中看到该条记录，可独立验证。

**Acceptance Scenarios**:

1. **Given** 已登录用户完成一次排盘，**When** 用户点击"保存"，**Then** 该排盘记录（含输入参数、人物关系标注与完整结果）被保存到该用户账户下并提示成功
2. **Given** 未登录用户完成一次排盘，**When** 用户点击"保存"，**Then** 系统引导用户完成登录，登录成功后回到保存流程
3. **Given** 用户保存排盘记录时填写备注，**When** 保存成功，**Then** 备注随记录一并保存并显示在记录列表中

---

### User Story 4 - 历史记录管理 (Priority: P3)

已登录用户可在"我的记录"中查看自己保存过的全部排盘记录，按时间倒序排列；可打开记录查看完整命盘，也可删除不再需要的记录。

**Why this priority**: 在保存能力之上提供管理与回看，增强长期使用价值。属于体验增强，可在前三个故事之后交付。

**Independent Test**: 已保存多条记录的用户能查看、打开、删除自己的记录，可独立验证。

**Acceptance Scenarios**:

1. **Given** 用户账户下已保存多条排盘记录，**When** 用户打开"我的记录"，**Then** 记录按人物与保存时间倒序展示，每条显示人物名称/关系、备注与排盘日期
2. **Given** 用户点击某条记录，**When** 打开详情，**Then** 显示该记录的完整排盘结果（与保存时一致）
3. **Given** 用户删除某条记录，**When** 确认删除，**Then** 该记录被移除且不再出现在列表中，其他记录不受影响

---

### User Story 5 - 分享命盘图片 (Priority: P3)

已登录或未登录用户可将当前排盘结果生成为一张命盘长图，并可保存到手机相册或分享到社交渠道（如微信）。分享内容为只读快照。

**Why this priority**: 分享是传播与留存的自然扩展，但依赖图片生成与渠道适配，非核心价值，作为 P3 在核心故事之后追加。

**Independent Test**: 用户完成一次排盘后一键生成长图，并可保存/分享，可独立验证。

**Acceptance Scenarios**:

1. **Given** 用户完成一次排盘，**When** 用户点击"生成图片"，**Then** 系统生成包含完整命盘（四柱、大运、流年、喜忌等）的长图
2. **Given** 图片已生成，**When** 用户点击"保存到相册"或选择分享渠道，**Then** 图片被保存或分享到所选渠道
3. **Given** 用户生成分享图片且其中包含姓名等个人信息，**When** 用户确认分享，**Then** 系统提示"图片含个人出生信息，请注意分享对象"，用户确认后继续

---

### Edge Cases

- 出生日期不合法（如 13 月、32 日、闰日不存在、日期在未来）：系统给出明确错误提示并阻止排盘
- 农历日期无效（如选择不存在的闰月）或农历换算超出支持范围：系统给出明确错误提示并阻止排盘
- 出生日期过于久远（如超过 120 年前）：系统提示超出范围，不执行排盘
- 出生时间精度不足（仅知道日期，不知时辰）：系统提示"无法计算时柱、命宫、身宫等时辰相关部分"，仍展示年月日柱，或引导用户补充
- 出生地点无法解析（境外、非中国大陆行政区划或名称不识别）：系统回退为东八区标准时间排盘，并在结果中明确标注
- 手机号格式错误或非中国大陆手机号：提示格式错误，不发送验证码
- 验证码获取过于频繁：提示"请求过于频繁，请稍后再试"，防止滥用
- 短信发送失败或网络异常：显示友好错误信息并允许重试，不丢失用户已填写的表单内容
- 同一手机号已在系统中存在：直接进入登录态，不重复创建账户、不覆盖原记录
- 闰月、节气交接临界时刻（如生日恰在立春前后、子时交界）：按既定排盘规则处理，并在结果中对存疑之处做标注
- 用户切换手机号登录：登录态切换为对应账户，只能看到新账户的记录
- 分享图片含个人信息（姓名、出生时间）：系统提示隐私风险，由用户确认后继续分享
- 命理解读的表述方式：解读为算法生成的参考信息，系统需在解读处提示"仅供参考"，不得使用绝对化、确定性断言

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许用户输入姓名、性别、出生日期时间、出生地点，并校验输入合法性（日期真实存在、时间格式正确）；出生日期时间支持公历与农历两种输入方式，可切换
- **FR-002**: 系统 MUST 根据出生时间与出生地点计算真太阳时；排盘口径为**年月柱按钟表时间（solar_birth）、日时柱按真太阳时（经出生地经度修正后的时间）**排出年、月、日、时四柱（含天干、地支、五行）——年柱/月柱的节气交接（立春定年、十二节定月）以钟表时间为界，日柱换日（子初换日）与时柱以真太阳时为界；未提供出生地点（无经度）时两者相同
- **FR-003**: 系统 MUST 在排盘结果中展示大运，包括起运岁数、各步大运的天干地支与起止年份
- **FR-004**: 系统 MUST 在排盘结果中展示流年，包括当前流年及未来 10 年的流年干支
- **FR-005**: 系统 MUST 在排盘结果中展示人元司令（各支所藏天干及当令信息）
- **FR-006**: 系统 MUST 在排盘结果中展示胎元、命宫、身宫
- **FR-007**: 系统 MUST 基于命局分析输出喜忌结论，至少包含用神、喜神、忌神，并提供"宜用五行、忌用五行"的通俗解读
- **FR-008**: 系统 MUST 允许用户使用中国大陆手机号 + 短信验证码完成注册与登录，注册与登录合一
- **FR-009**: 系统 MUST 对未登录用户开放排盘功能，仅在保存记录、查看历史记录时要求登录
- **FR-010**: 系统 MUST 允许已登录用户保存排盘记录（本人或家人），记录包含输入参数、完整排盘结果、人物名称与关系标注（本人/子女/父母/其他，默认"本人"）及可选备注
- **FR-011**: 系统 MUST 允许已登录用户查看、打开、删除自己保存的排盘记录
- **FR-012**: 系统 MUST 保证用户只能访问属于自己的排盘记录，无法查看或操作他人记录
- **FR-013**: 系统 MUST 在移动设备上提供良好的使用体验（界面适配手机屏幕、触控友好、输入表单简洁）
- **FR-014**: 系统 MUST 对用户出生信息与排盘结果进行隐私保护，不得向其他用户或第三方泄露
- **FR-015**: 系统 MUST 允许用户将当前排盘结果生成为一张完整的命盘图片（长图）
- **FR-016**: 系统 MUST 允许用户将生成的命盘图片保存到手机相册或分享到社交渠道（如微信）
- **FR-017**: 系统 MUST 在喜忌分析中展示分析依据，包括日主强弱、五行旺衰与用神取法说明
- **FR-018**: 系统 MUST 提供简要的命理解读，至少包含十神分析及事业、财运、健康方向的方向性解读
- **FR-019**: 系统 MUST 在命理解读处注明"内容为算法生成的参考信息，仅供参考"，不使用绝对化或确定性断言
- **FR-020**: 系统 MUST 支持农历日期输入并正确换算为公历（含闰月处理）后执行排盘，结果页同时展示公历与农历日期

### Key Entities *(include if feature involves data)*

- **用户（User）**: 一个账户，以中国大陆手机号作为唯一登录凭证。属性：手机号、登录会话、姓名（可选）、性别（可选）、注册时间。与排盘记录为 1-N 关系。
- **排盘记录（BaziChart）**: 用户保存的一次排盘。属性：输入参数（姓名、性别、出生时间、出生地点）、完整排盘结果、人物名称与关系（本人/子女/父母/其他，默认"本人"）、备注、保存时间。属于一个用户（N-1），用户删除后记录一并移除。
- **排盘结果（ChartResult）**: 一次计算得到的命盘数据，含四柱、大运序列、流年序列、人元司令、胎元、命宫、身宫、喜忌分析（结论、分析依据与方向解读）。既可作为排盘记录的组成部分，也可独立存在（供未登录用户临时查看）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从进入排盘页到看到完整命盘结果，全程不超过 2 分钟
- **SC-002**: 对同一组输入，系统排盘结果（四柱、起运岁数、胎元/命宫/身宫）与公认权威排盘结果一致；抽检 100 组不同输入准确率达到 100%
- **SC-003**: 用户使用手机号完成注册并登录，全程不超过 1 分钟
- **SC-004**: 登录用户重新进入应用后，能在 3 步操作之内找到并打开自己保存过的排盘记录
- **SC-005**: 排盘结果中的喜忌结论与命理解读通俗易懂，90% 以上的目标用户表示"能看懂、知道怎么用"
- **SC-006**: 任何用户无法通过任何入口访问其他用户的排盘记录（数据隔离零泄漏）
- **SC-007**: 用户在点击"开始排盘"后，在常见移动网络环境下 5 秒内看到完整排盘结果；登录、保存等操作无显著感知延迟
- **SC-008**: 用户能在 1 步操作内将命盘生成为图片并保存/分享，生成的图片内容清晰可读

## Assumptions

- 排盘采用子平法（以节气定月柱、以日主强弱定喜忌）作为唯一算法流派，v1 不提供流派切换
- 出生地点仅用于计算真太阳时；无法解析的地点回退为东八区标准时间并明确标注
- 出生时间精度最低支持到"时辰"；仅知道日期时，无法计算的时辰相关部分（时柱、命宫、身宫）将缺失并在结果中提示
- 手机号仅限中国大陆 11 位手机号（1 开头）
- 登录采用短信验证码、不设密码；实名认证不在 v1 范围
- v1 对用户可保存的排盘记录条数不做限制
- v1 以移动端体验为优先，桌面端可用但不做专门优化
- 需要对接短信服务商以发送验证码
- 用户的出生信息与排盘结果属于敏感个人数据，需遵循隐私保护与数据最小化原则
- 排盘计算的执行位置（客户端或服务端）由实现阶段决定，本规范只约束用户可见行为
