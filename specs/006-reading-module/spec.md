# Feature Specification: 阅读模块（Books & Reading）

**Feature Branch**: `006-reading-module`  
**Created**: 2026-08-13  
**Status**: Draft  
**Input**: User description: "新加一个阅读模块，后台可以维护书籍录入书籍章节和每个章节得内容，前台用户可以直接查看书籍得内容"

## Clarifications

### Session 2026-08-13

- Q: 章节内容格式？ → A: 章节正文采用 Markdown 文本存储与渲染；后台提供输入与预览，不做所见即所得编辑器；图片上传不在本期范围（封面用外链 URL）
- Q: 书籍可见性控制？ → A: 书籍有「草稿/已发布」状态，仅已发布书籍对前台用户可见；管理员手动发布
- Q: 阅读与维护权限？ → A: 阅读复用全应用登录体系（全应用需登录，未登录跳登录页）；书籍/章节维护仅管理员，服务端强制 `require_admin` + 审计
- Q: 书籍分类？ → A: 单级分类——每本书归属一个分类（如「命理/国学」），后台可维护分类，前台书籍列表可按分类筛选
- Q: 删除含章节的书籍策略？ → A: 级联删除其全部章节，操作前二次确认
- Q: 阅读进度记忆？ → A: 按「用户+书籍」记录当前章节，再次打开该书时直达上次章节；不做滚动位置记忆，不同用户进度互不影响

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 后台录入与维护书籍 (Priority: P1)

管理员在后台维护书籍：录入书名（必填）、作者、简介、封面、所属分类，可编辑、删除、发布/取消发布；书籍列表支持分页与按书名搜索，后台可维护分类。

**Why this priority**: 书籍是阅读模块的根对象，没有书籍就无法录入章节与阅读，是后续所有能力的基础。

**Independent Test**: 管理员创建一本书并保存 → 列表可见；修改书名后保存 → 内容更新；发布后前台可见、取消发布后前台消失；删除后列表移除。可独立验证。

**Acceptance Scenarios**:

1. **Given** 管理员登录并进入书籍维护页，**When** 填写书名与作者/简介/封面/分类并提交，**Then** 书籍创建成功并出现在列表中
2. **Given** 书籍列表，**When** 管理员编辑某本书的信息并保存，**Then** 展示更新后的内容
3. **Given** 书籍较多，**When** 管理员浏览列表，**Then** 支持分页与按书名搜索
4. **Given** 一本草稿书籍，**When** 管理员点击「发布」，**Then** 前台用户立即可见；取消发布后前台立即不可见
5. **Given** 一本含章节的书籍，**When** 管理员删除并确认，**Then** 该书与其全部章节一并移除，不再出现在任何列表
6. **Given** 非管理员用户访问维护页，**When** 尝试操作，**Then** 拒绝访问并提示无权限
7. **Given** 后台分类维护页，**When** 管理员新增/编辑/删除分类，**Then** 书籍的分类选项同步更新

---

### User Story 2 - 后台录入章节与内容 (Priority: P1)

管理员在某一本书下录入章节：章节标题（必填）+ 章节内容（Markdown 文本），可新增、编辑、删除、调整顺序；章节按顺序在阅读页展示。

**Why this priority**: 章节与内容是阅读模块的核心交付物，书籍的价值体现在章节内容上，与故事 1 共同构成 MVP。

**Independent Test**: 为某本书录入 3 个章节 → 前台阅读页按顺序展示且内容正确；调整顺序后顺序更新；删除章节后剩余顺序正确。可独立验证。

**Acceptance Scenarios**:

1. **Given** 一本书，**When** 管理员新增章节并填写标题与内容，**Then** 章节出现在该书章节列表末尾
2. **Given** 章节列表，**When** 管理员编辑某章节的标题/内容并保存，**Then** 前台展示更新后的内容
3. **Given** 章节列表，**When** 管理员调整章节顺序，**Then** 前台按新顺序展示
4. **Given** 某章节，**When** 管理员删除，**Then** 章节移除，其余章节顺序正确
5. **Given** 无章节的书籍，**When** 前台打开，**Then** 展示「暂无章节」空状态，不报错

---

### User Story 3 - 前台阅读书籍 (Priority: P1)

登录用户可浏览已发布书籍列表（支持按分类筛选），打开一本书查看章节目录，点击章节阅读内容，支持上一章/下一章逐章切换；系统记住每本书上次读到的章节，再次打开直达该章节。

**Why this priority**: 阅读是用户侧的核心价值，直接服务最终用户，与后台录入能力共同构成完整功能闭环。

**Independent Test**: 用户浏览书籍列表 → 打开一本书 → 阅读章节 → 通过上一章/下一章逐章浏览。可独立验证。

**Acceptance Scenarios**:

1. **Given** 登录用户进入阅读入口，**When** 浏览书籍列表，**Then** 仅展示已发布书籍（书名/封面/简介），并可切换分类筛选
2. **Given** 一本书，**When** 用户打开，**Then** 展示章节目录，点击章节进入内容页
3. **Given** 章节内容页，**When** 用户阅读，**Then** 内容完整展示，并提供「上一章/下一章」切换
4. **Given** 用户读到第一章/最后一章，**When** 点击上一章/下一章，**Then** 给出已到首/尾的提示，不报错
5. **Given** 未登录用户访问阅读页，**When** 尝试打开，**Then** 按全应用规则跳转登录页，登录后回跳
6. **Given** 用户已阅读某本书至第 N 章，**When** 再次打开该书，**Then** 直达第 N 章内容；另一用户打开该书各自回到自己的进度

---

### Edge Cases

- **书籍无章节**：前台打开显示「暂无章节」空状态，后台仍可正常新增章节
- **章节标题为空**：保存时校验必填，不落库
- **长章节内容**：阅读页支持滚动浏览，不截断、不卡顿
- **未发布书籍**：前台任何入口（列表/搜索/直接链接）均不可见；已发布后立即可见
- **删除含章节的书籍**：级联删除，删除前二次确认
- **非管理员访问维护接口/页面**：服务端 `require_admin` 拒绝并审计，前端提示无权限
- **并发编辑**：v1 采用「最后写入生效」，不做版本冲突处理
- **封面为空**：列表展示默认占位图，不报错

## Requirements *(mandatory)*

### Functional Requirements

**后台书籍维护**

- **FR-001**: 管理员 MUST 能创建书籍，书名必填，作者/简介/封面可选；**创建时分类必填**（删除所属分类后书籍可处于「未分类」）
- **FR-002**: 管理员 MUST 能分页浏览书籍列表并按书名搜索，能编辑与删除书籍
- **FR-003**: 每本书 MUST 有发布状态（草稿/已发布）；未发布书籍对前台用户 MUST 不可见
- **FR-004**: 书籍与章节的维护能力 MUST 仅管理员可用（服务端强制 `require_admin` + 审计）
- **FR-004a**: 管理员 MUST 能维护单级分类（新增/编辑/删除/排序），删除分类时其下书籍分类**置为「未分类」（category_id 置 NULL）**；书籍录入/编辑时分类从既有分类中选择

**后台章节维护**

- **FR-005**: 管理员 MUST 能在某本书下新增章节，章节标题必填、内容为 Markdown 文本，新章节排在末尾；后台提供输入与预览
- **FR-006**: 管理员 MUST 能编辑、删除章节，并调整章节顺序；顺序 MUST 持久化并在前台按序展示

**前台阅读**

- **FR-007**: 登录用户 MUST 能浏览已发布书籍列表（含书名/封面/简介/分类），并支持按分类筛选
- **FR-008**: 登录用户 MUST 能打开书籍查看章节目录，并阅读章节内容
- **FR-009**: 章节内容页 MUST 提供上一章/下一章导航，到首/尾时给出明确提示
- **FR-010**: 阅读入口 MUST 复用全应用登录体系；未登录访问跳转登录页，登录后回跳
- **FR-010a**: 系统 MUST 按「用户+书籍」记录当前阅读章节，再次打开该书时直达上次章节；不同用户进度互不影响

**数据一致性**

- **FR-011**: 书籍与章节数据 MUST 持久化存储，跨会话与设备一致
- **FR-012**: 前台 MUST 只能读到已发布书籍的章节内容；未发布书籍及其章节对用户整体不可见，后台草稿正文 MUST 不向用户泄露

### Key Entities

- **书籍（Book）**: 一本阅读作品的元数据——书名、作者、简介、封面、所属分类、发布状态、创建/更新时间；包含多个章节
- **章节（Chapter）**: 一本书下的一个章节——所属书籍、标题、内容（Markdown 文本）、排序号、创建/更新时间
- **分类（Category）**: 单级书籍分类——名称、排序号；一本书归属一个分类。「未分类」表示书籍 `category_id` 为 NULL（删除分类后可能产生）
- **阅读进度（Reading Progress）**: 按「用户+书籍」记录的当前阅读章节，用于再次打开时直达

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理员可在 3 分钟内完成「创建书籍 + 录入 3 个章节 + 发布」全流程
- **SC-002**: 前台用户从浏览书籍列表到打开章节内容，操作 ≤ 3 步且全程无报错
- **SC-003**: 未发布（草稿）书籍在任何前台用户入口的出现率为 0%
- **SC-004**: 发布/取消发布、章节增删改在保存后，对相应角色的可见性在 1 秒内生效（默认无缓存即达，无需专项任务）
- **SC-005**: 1 万字以上的长章节打开后能正常滚动阅读，无卡顿与截断

## Assumptions

- 内容格式：章节内容采用 Markdown 文本存储与渲染（覆盖标题/段落/列表/加粗等），后台提供输入与预览；图片上传不在本期范围
- 访问权限：复用全应用登录体系（全应用需登录）；阅读仅登录用户可见；书籍/章节维护仅管理员（沿用现有服务端 `require_admin` + 审计）
- 管理后台形态：后台维护页置于独立 admin 前端应用（`admin/`，Element Plus）；`frontend/` 仅承载用户端页面
- 发布流程：书籍默认以「草稿」创建，管理员手动发布后才对前台可见
- 删除策略：删除书籍时级联删除其章节，操作前二次确认
- 存储：书籍/章节存入现有腾讯云 MySQL，不引入新存储
- 数据规模：v1 面向少量书籍（预计 <1000 本），列表分页即可，无需搜索引擎；封面为外链 URL，不提供上传
