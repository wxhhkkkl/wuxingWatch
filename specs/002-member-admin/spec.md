## User Scenarios & Testing *(mandatory)*

### User Story 1 - 手机号 + 密码注册与登录 (Priority: P1)

用户在手机端或网页注册时，先经短信验证手机号归属，再设置密码（手机号即用户名）；之后可直接用「手机号 + 密码」登录，无需每次接收短信验证码。密码以安全方式存储。

**Why this priority**: 登录方式是会员使用产品的基础，密码登录相比短信验证码更稳定、无短信成本，是会员留存的基础能力。

**Independent Test**: 新用户注册一个手机号+密码账户，并用该组合成功登录；错误密码无法登录。可独立验证。

**Acceptance Scenarios**:

1. **Given** 用户进入注册页，**When** 填写手机号 → 接收短信验证码验证归属 → 设置密码并提交，**Then** 账户创建成功并可直接登录
2. **Given** 用户已有账户，**When** 使用手机号 + 正确密码登录，**Then** 登录成功进入应用
3. **Given** 用户输入错误密码，**When** 提交登录，**Then** 提示密码错误且不进入登录态
4. **Given** 用户使用已被注册的手机号注册，**When** 提交，**Then** 提示手机号已存在，并引导登录或设置密码

---

### User Story 2 - 数据库迁移至腾讯云 MySQL (Priority: P1)

系统的数据存储由本地 SQLite 切换为腾讯云 MySQL。迁移后，既有用户、排盘记录等数据完整保留，系统在云数据库上正常运行。

**Why this priority**: 云数据库是生产环境稳定运行的前提，用户名+密码登录与后台管理均依赖新的数据库环境，须先完成。

**Independent Test**: 迁移完成后，用迁移前的同一组账户登录并查看迁移前的排盘记录，数据一致；可独立验证。

**Acceptance Scenarios**:

1. **Given** 系统已配置腾讯云 MySQL 连接，**When** 启动系统，**Then** 系统连接云数据库并正常运行
2. **Given** 迁移脚本执行完成，**When** 核对数据，**Then** 用户与排盘记录数量及内容与迁移前 100% 一致，无丢失
3. **Given** 迁移期间，**When** 系统切换数据库，**Then** 迁移过程有明确的窗口与回滚方案，失败时不破坏源数据
4. **Given** 云数据库不可用时，**When** 系统请求数据，**Then** 给出明确错误提示而非静默失败

---

### User Story 3 - 管理员登录后台 (Priority: P2)

管理员凭账号密码登录后台管理页面（浏览器访问）；管理员账号必须先设置密码（经短信验证），或后台登录同样支持短信验证码。非管理员无法进入后台。

**Why this priority**: 后台管理是运营查看会员与排盘的前提，须先有受控的管理员身份。

**Independent Test**: 管理员账号登录后台成功；普通会员账号访问后台被拒绝。可独立验证。

**Acceptance Scenarios**:

1. **Given** 管理员输入后台账号密码，**When** 提交登录，**Then** 进入后台管理页面
2. **Given** 普通会员账号尝试访问后台，**When** 提交，**Then** 被拒绝且提示无权限
3. **Given** 未登录用户直接访问后台地址，**When** 打开页面，**Then** 被引导至管理员登录页

---

### User Story 4 - 会员与排盘管理 (Priority: P2)

管理员登录后台后，可查看已注册会员列表（含会员总数统计，支持分页与按手机号搜索），并可查看指定会员名下保存的排盘记录。查看仅限管理员角色，会员数据按最小必要展示。

**Why this priority**: 这是运营管理的核心诉求，用于了解会员规模与使用情况。

**Independent Test**: 管理员在后台看到会员列表，点开某会员可看到其排盘记录列表与详情。可独立验证。

**Acceptance Scenarios**:

1. **Given** 后台存在多位注册会员，**When** 管理员打开"会员管理"，**Then** 展示会员总数统计，并按注册时间倒序分页展示会员列表（含手机号与注册时间）
2. **Given** 管理员点击某会员，**When** 查看详情，**Then** 展示该会员的基本信息与其保存的排盘记录列表
3. **Given** 管理员点击某条排盘记录，**When** 查看，**Then** 展示该记录的完整排盘结果（与会员视角一致）
4. **Given** 后台展示会员数据，**When** 渲染页面，**Then** 只展示管理所需的最小字段，不泄露无关敏感信息
5. **Given** 管理员输入某会员手机号，**When** 提交搜索，**Then** 精准返回该会员（存在时），无匹配时提示"未找到该会员"

---

### Edge Cases

- 手机号格式非法或长度不合法：给出格式提示，拒绝注册
- 手机号已被注册：提示手机号已存在（见 US1 场景 4）
- 密码过弱（过短/纯数字等）：提示设置更强密码
- 登录失败次数过多：临时锁定或增加验证，防止暴力破解
- 同一手机号账户拥有两种登录方式（密码 / 短信验证码），任一方式登录后均为同一账户，数据互通
- 数据迁移中断或部分失败：回滚到源 SQLite，源数据不被破坏；重试迁移
- 云数据库连接串泄露风险：连接凭据仅存于服务端配置，不进入前端或版本库
- 管理员误操作：后台只读查看，v1 不提供删除/修改会员能力（避免运营风险）
- 被提升为管理员但未设置密码：登录后台时引导其先经短信验证设置密码
- 会员被删除或账户异常时的后台展示：显示"已注销/不可用"状态而非报错
- 后台页面在手机小屏访问：可查看但优先桌面布局（v1 不做专门移动适配）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 允许用户注册「手机号 + 密码」账户（手机号即用户名，全局唯一且符合手机号格式）；注册前 MUST 先经短信验证该手机号归属
- **FR-002**: 系统 MUST 允许用户使用「手机号 + 密码」登录；密码 MUST 以不可逆哈希存储，不得明文保存或传输；设置/重置密码 MUST 先经短信验证身份
- **FR-003**: 系统 MUST 支持「手机号 + 密码」与「手机号 + 短信验证码」两种登录方式并存，均作为会员的合法登录方式，同一账户数据互通
- **FR-004**: 手机号即用户名，不设额外用户名字段；登录与注册均以手机号作为账号标识
- **FR-005**: 系统 MUST 支持连接腾讯云 MySQL 作为数据存储，本地 SQLite 仅保留为开发/测试环境选项
- **FR-006**: 系统 MUST 提供一次性数据迁移能力，将既有用户与排盘记录完整迁移至云 MySQL，不丢失数据
- **FR-007**: 系统 MUST 提供管理员账号体系（独立角色），管理员可通过账号密码登录后台；管理员账号需已设置密码（经短信验证），未设置密码的管理员不可登录后台
- **FR-008**: 系统 MUST 保证仅管理员角色可访问后台，普通会员与未登录用户均无法访问
- **FR-009**: 系统 MUST 在后台提供会员列表：按注册时间倒序分页展示，支持按手机号精确搜索，并展示会员总数统计；列表字段为最小必要（手机号、注册时间）
- **FR-010**: 系统 MUST 允许管理员查看指定会员名下保存的排盘记录（列表与完整结果）
- **FR-011**: 系统 MUST 对后台所有端点强制管理员鉴权（服务端校验，非仅前端），会员数据查看遵循最小化与脱敏原则，符合隐私保护

### Key Entities *(include if feature involves data)*

- **用户（User）**: 增加账号属性：密码哈希、角色（会员/管理员）。手机号即账号标识（不设额外用户名），既有属性（手机号、姓名、性别）保留。会员与管理员为同一实体按角色区分。
- **排盘记录（BaziChart）**: 不变，仍归属用户（会员）；后台按会员查看其记录。
- **登录会话（RefreshSession）**: 管理员登录复用现有会话机制，不设独立 AdminSession；管理员身份由 User.role 判定。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 数据迁移后，用户与排盘记录的数量和内容与迁移前 100% 一致，迁移过程可在 ≤30 分钟的维护窗口内完成
- **SC-002**: 用户注册并首次用用户名+密码登录，全程不超过 1 分钟
- **SC-003**: 管理员登录后台并找到指定会员及其排盘记录，全程不超过 1 分钟
- **SC-004**: 普通会员与未登录用户尝试访问后台，100% 被拒绝（零越权）
- **SC-005**: 密码不以明文形式存储在数据库或日志中（审计抽检为 0 处）
- **SC-006**: 系统在云 MySQL 上运行；数据库连接故障时返回明确错误提示而非崩溃，服务不因单次连接失败中断

## Assumptions

- 已确认：**手机号+密码** 与 **手机号+短信验证码** 两种登录方式并存，均为会员合法登录方式
- 已确认：**手机号即用户名**，不设额外用户名字段
- 已确认：注册、设置/重置密码均需短信验证手机号归属（防冒用与假会员）
- 既有手机号用户可经短信验证身份后设置/重置密码；新用户可直接以手机号+密码注册
- 首个管理员账号通过初始化脚本/环境变量创建，不在前台开放注册
- 后台为独立的管理页面（浏览器访问、桌面布局优先），与会员移动端应用分离
- 需要用户提供腾讯云 MySQL 的连接配置（地址、端口、库名、账号、密码）并配置安全组白名单
- 数据迁移在选定的维护窗口一次性执行，迁移期间服务短暂不可用；提供回滚方案
- 密码策略采用常见强度要求（最小长度、避免常见弱密码）
- 后台 v1 只读查看会员与排盘，不提供新增/修改/删除运营功能
