# Phase 0 Research: 旺度计算顺序重构——阶段一静态（地支）→ 阶段二动态（天干）

**Feature**: `009-wangdu-static-dynamic` | **Date**: 2026-08-19 | **Branch**: `009-wangdu-optimization`
**依据**: [spec.md](spec.md)（含 Clarifications Q1-Q5）+ [008 algorithm-reference](../008-yongshen-steps/algorithm-reference.md) + 现状代码 `backend/src/services/bazi/wangdu.py`、`frontend/src/utils/relations.ts`

## R1: 两阶段流水线——现状重组为 静态(地支)→动态(天干)

- **Decision**: `compute_wangdu` 内部执行顺序重组为两阶段：
  - **阶段一 静态旺度**（只动地支）：① `_build_cols` 列出原始藏干；② 地支关系判定+修正（仅 branch 层，按书论处先后，只改藏干度数）；③ `_wx_degrees` 通根运算（连片/距离衰减/月令特权，对修正后藏干）；④ × 月令系数（含戌月燥土、月令被合化双状态平均）→ 各天干、各藏干静态分数。
  - **阶段二 动态旺度**（开始天干作用）：⑤ **动态 A**——紧贴三对（年干-月干、月干-日干、日干-时干），每对先判天干五合（争合/合化/合绊贪合忘生克），无五合再走普通生克；⑥ **动态 B**——同柱天干↔本柱全部藏干配对运算。
  - ⑦ 合并修正后天干 + 修正后藏干 → 各五行**最终旺度**；⑧ 下游 geju / dayun_adjustments / yongshen **沿用 008 期不变**。
- **Rationale**: 用户核心指令"静态只管地支结构、天干保持原始状态；天干五合属天干'生克作用体系'归动态"。现状代码顺序为 `static → 关系判定(天干+地支合并) → 同柱生克 → 天干五合 → 地支刑冲合害 → final`，地支修正在天干之后，与新口径相反，必须重排。
- **Alternatives**: 仅在展示层重排步骤、计算不动（被否——用户要的是计算顺序本身）；新增独立静态/动态两个引擎模块（被否——同文件内顺序重排即可，避免无谓拆分）。

## R2: 地支论处先后按《四柱精髓》书原文（澄清 Q3）

- **Decision**: 静态阶段地支论处先后以书原文为准（取代 008 与用户最初简化版）：
  - 全局（含天干项）：天合地合＞（不成功则）天克地冲＞辰戌丑未土局＞丑未戌＞三支自刑（三辰自刑除外）＞会局＞三合局＞生地半三合＞六冲＞六合＞墓地半三合（巳酉合等同墓地半三合）＞子卯刑/寅巳申刑/两支自刑/丑未戌两支相刑＞六害。
  - 地支层（阶段一用，过滤天干项）：**辰戌丑未土局 ＞ 丑未戌三刑 ＞ 三支自刑 ＞ 会局（三会）＞ 三合局 ＞ 生地半三合 ＞ 六冲 ＞ 六合 ＞ 墓地半三合（含巳酉）＞ 子卯/寅巳申/两支自刑/丑未戌两支刑 ＞ 六害**；破不在书中体系、保留排最后。
- **Rationale**: 用户明确"书这样说"，为权威口径。现状 `_branch_pair_types`（后端）与 `branchPairTypes`（前端）均为"生地半三合＞相冲＞六合＞墓地半三合＞刑＞害＞破"，且三合/三会/三刑在让位时未进入同一优先级表——需统一重写为分层排序函数（对与三支关系共用）。
- **实现要点**: 新增统一的 `branch_priority_tier(type, 具体关系)` 排序：地支对/三支关系都映射到 1~12 层；同一对多字面关系只保留最高层（现状逻辑复用）；三合/三会/三刑/四库土局与两两关系一并参与让位。
- **Alternatives**: 保持 008 优先级只换半三合位置（被否——书原文明确六冲在六合前、六害最后，且用户要求按书）。

## R3: 动态 A——紧贴天干三对，五合先于生克

- **Decision**: 动态 A 只处理紧贴三对（年-月、月-日、日-时），不再处理"中隔同类可论生克"的放宽。每对流程：
  1. 判该对是否有**天干五合**（含争合/妒合=争合：同一干被两干合 → 力量大者优先、势均力敌双方合绊）。
  2. 有五合 → 判合化条件（`_stem_he_hua_ok` 复用）：合化成功 → 两干废弃原五行、按化神五行记账（`gan_hua`）；合而不化 → **合绊**：只改两干旺度（主克 ×0.8、受克 ×0.5，**澄清 Q1 沿用 008 C8**），该对**不再执行普通相生相克倍率**（贪合忘生克）。
  3. 无五合 → 普通生克：判生克权（≥2.4）、套同性/异性倍率。
- **Rationale**: 用户核心指令 + Q1/Q2 澄清。"贪合忘生克"在 008 中因每对只产一种关系（五合或生克）本就成立，本期在动态 A 中显式声明并按紧贴三对重排判定。
- **Alternatives**: 保留 008"相邻+中隔同类放宽"（被否——用户明确"紧贴天干之间作用"，只三对）。

## R4: 动态 B——同柱生克扩展到全部藏干（澄清 Q4）

- **Decision**: `_apply_tongzhu`（008 C20，现只对支**本气**）扩展为对**本柱全部藏干**（本气/中气/余气）逐个配对，数值沿用 008 同柱生克系数公式：主方（生者/克者）旺度 ≥2.4 生效；同性相生 主×0.7/受×1.3、异性 主×0.8/受×1.2；同性相克 主×0.7/受×0.5、异性 主×0.7/受×0.6；主生太旺（≥26）而受生无权 → 受生反减 5 成；主克数倍于受克（≥4倍）→ 受克归零、主克耗 1 成。执行顺序：动态 A **之后**。
- **Rationale**: 澄清 Q4 明确"全部藏干逐个套用 008 公式"。作用对象从支本气扩展到全部藏干是本期"甲木版本删掉、许心友原著保留"的差异点。
- **Alternatives**: 本气用公式、中气/余气简化增减（用户未选，选 A 全套公式）。

## R5: 步骤与数据模型演进

- **Decision**: `xi_yong.strength.steps` 步骤键重组为：`static`（阶段一：原始藏干→地支关系→通根→×系数，traces 含 4 段明细）→ `dynamic_a`（动态 A 紧贴天干五合/生克）→ `dynamic_b`（动态 B 同柱生克）→ `final` → `geju` → `dayun` → `yongshen`。**移除 `shengke`/`zhichong` 两个旧键**（其语义被 `static`（地支修正）+ `dynamic_a/b`（天干修正）取代）。`static_scores` 保持 `map<五行, number>`（下游兼容），个体分数以 traces 逐条呈现。
- **Rationale**: 前端 `StrengthDetail.vue` 按 `s.key/s.title/traces/result` 泛化渲染（grep 确认），步骤重组基本是后端驱动、前端无硬编码键值；`types.ts` 的 `WangduStep.key` 若为 string 类型无需改（计划阶段核对）。
- **Alternatives**: 保留旧键名仅换内容（被否——键名与阶段语义不符，误导前端）；步骤拆成 8+ 个更细键（被否——保持 7 键与 008 数量一致、差异最小）。

## R6: 前端命盘图关系判定同步（澄清 Q5）

- **Decision**: 前端 `relations.ts` 的 `branchPairTypes` 优先级与让位逻辑同步为书原文（同 R2 分层表）；`buildRelationJudgments` 三支关系（三合/三会/三刑/四库土局）纳入统一优先级。`StrengthDetail.vue` 步骤渲染随后端新键自然生效（泛化渲染）。对拍测试（relation-graph.spec.ts / relations.spec.ts）同步更新锚点。
- **Rationale**: 澄清 Q5 明确"本期同步，与后端同口径"，避免 008 SC-005"图上判定与喜忌步骤一致"被破坏。
- **Alternatives**: 前端不动（被否——Q5 选 A）；前端仅改优先级不改让位（被否——同一口径必须完整）。

## R7: TDD 测试策略

- **Decision**: 先写失败测试再实现（宪法 II）：
  - **后端** `test_wangdu.py` 新增锚点：
    1. **静态阶段天干五合零影响**——构造"地支完全相同、仅天干五合组合不同"的对照盘，断言 `static` 步各天干/藏干分数完全一致；
    2. **地支论处先后**——六冲+六合并见 → 六冲让位六合让位（书：六冲先于六合）；生地半三合 vs 六冲让位；
    3. **动态 A 仅紧贴三对**——隔位天干生克不入动态 A，无修正记录；
    4. **合绊贪合忘生克**——合绊对无普通生克倍率 trace；
    5. **动态 B 全部藏干**——中气/余气藏干参与配对，断言数值；
    6. **008 期锚点重跑**——逐例断言新结果，与 008 差异记录于对照测试报告并重定锚点。
  - **前端** `relations.spec.ts` / `relation-graph.spec.ts`：优先级表更新 + 构造盘断言。
  - **契约** `test_charts_api.py`：步骤键断言改为 7 键新序列。
- **Rationale**: 算法顺序重构的正确性验证必须落在"新旧顺序差异"的可观测断言上（静态五合零影响是最强判据）；008 已有 10 个书中命例锚点，重跑并记录差异是验收基准（SC-006）。
- **Alternatives**: 仅重跑 008 锚点不看差异（被否——顺序改变必然引起部分数值变化，必须逐例说明原因）。

## R8: 遗留裁定（Deferred，计划落地时固化）

- **天合地合/天克地冲**：书全局优先级最高两项涉及"天干+地支"同对并见。两阶段模型下按"地支部分入阶段一、天干部分入阶段二"拆分判定；跨层让位（如同一柱对的天合+地合组合）在计划实现时按原文最小落地，不引入额外状态。
- **辰戌丑未土局（四库土局）**：书优先级最高地支项。现状代码无独立"四库土局"判定（辰戌/丑未按冲、丑未戌按三刑）。计划阶段按原文确认四库土局的成立条件与度数影响；若原文未量化则按"优先级占位 + 不单独加减力"最小实现（与 008 C4 冲动同策略）。
- **三支自刑 vs 两支自刑分层**：书将三支自刑（三辰除外）排在高优先级、两支自刑排在低优先级。现状 `_zixing_ok` 已按支数分条件，计划阶段将自刑并入分层排序（三支档位高于两支档位）。
- **破（ZHI_PO）**：不在书中体系，保留排最后（现状一致），不参与优先级让位争夺。
