# Research: 命盘图（干支 · 流通 · 宫位 · 六亲 可视化）

> Phase 0 产物。目标：把 spec 中所有待定/模糊点收敛为确定规则，供 data-model 与 tasks 使用。
> 本功能无新技术选型（纯前端可视化），本文件以「领域规则确认 + 数据可用性核查」为主。

## 1. 五行相生相克规则

**Decision**: 流通箭头关系采用标准五行循环，与后端 `backend/src/services/bazi/constants.py:38-40` 完全一致：

```
相生 SHENG: 木→火→土→金→水→木   （若 SHENG[甲] == 乙 则 甲生乙）
相克 KE:    木→土→水→火→金→木    （若 KE[甲] == 乙 则 甲克乙）
比和:       两五行相同
```

**Rationale**: 与后端排盘引擎的十神判定（`shishen()` 同样基于 SHENG/KE）保持同一套规则，避免前端展示与后端领域逻辑出现分歧。
**Alternatives considered**: 前端另写一套映射表（复制常量）——否决，改为从前端 `utils/relations.ts` 内联定义同一映射并加单测锚定，成本低且可回归。

## 2. 流通箭头的方向与关系语义

**Decision**: 箭头方向固定为位置流（年→月→日→时，即"前者指向后者"，spec FR-005）；天干层与地支层分开，各自只连接相邻柱（年↔月、月↔日、日↔时）。关系标签为**无向**的生/克/比：对两个不同五行，必居其一（比和之外，非生即克），用 `SHENG`/`KE` 双向判定：

```
wuxingRelation(a, b):
  a == b              → 'bi'   （比和，灰 + 「比」）
  SHENG[a] == b 或 SHENG[b] == a → 'sheng'  （相生，绿 + 「生」）
  KE[a] == b 或 KE[b] == a       → 'ke'     （相克，红 + 「克」）
```

**Rationale**: 相邻两元素的生/克关系是元素对本身的属性，不依赖方向；方向仅表达位置流动，避免「被克」这类需要额外语义的标签，让色盲可读的文字标注保持单一汉字（生/克/比）。
**Alternatives considered**: 方向沿生克方向绘制（如 木生火则箭头指向火）——否决，会造成箭头在柱间来回交错、方向不连贯，违背"流通"从年到时的直觉流向。

## 3. 宫位六亲映射

**Decision**: 采用通用四柱宫位固定映射（spec Assumptions）：

| 柱 | 宫位 | 六亲 |
|----|------|------|
| 年柱 | 祖上宫 | 祖辈/长辈 |
| 月柱 | 父母宫 | 父母 |
| 日支 | 配偶宫 | 配偶 |
| 时柱 | 子女宫 | 子女 |

**Rationale**: 业界通行约定，无歧义；月柱兼主兄弟信息只作图例备注，不在柱内分拆。
**Alternatives considered**: 自定义宫位命名——否决，通用命名用户熟悉度最高。

## 4. 十神 ↔ 六亲映射（含性别差异）

**Decision**: 图例采用通用简化映射，性别差异以备注呈现（spec FR-008）：

| 十神组 | 六亲（通用） | 性别差异备注 |
|--------|--------------|--------------|
| 印（正印/偏印） | 父母（偏印亦主母） | 男/女命通用 |
| 官杀（正官/七杀） | 丈夫（女命）/ 上级 | 男命正官主女儿、七杀主儿子 |
| 财（正财/偏财） | 妻（男命）/ 父亲 | 女命正财主父亲 |
| 比劫（比肩/劫财） | 兄弟姐妹 | 男/女命通用 |
| 食伤（食神/伤官） | 子女 | 女命食神主女儿、伤官主儿子 |

**Rationale**: 覆盖五组十神，逐条注明性别差异（spec 用户故事 4 要求），避免用户误读。
**Alternatives considered**: 在柱内直接标具体亲眷（如"母亲"）——否决，映射随性别/命主身份变化大，图例表更稳。

## 5. 数据可用性核查（无后端改动即可实现）

**Decision**: `ChartResult` 既有字段已覆盖图示全部数据需求：

| 图示元素 | 数据来源（frontend/src/types.ts） |
|----------|----------------------------------|
| 四柱干支 / 五行 | `pillars.{year,month,day,time}.gan/zhi/gan_wuxing/zhi_wuxing` |
| 天干十神 | `pillar.shishen`（以日主为基准） |
| 藏干十神 | `pillar.detail?.cang_gan[]`（`gan` + `shishen`） |
| 日主 | `result.day_master` |
| 缺失标记 | `result.missing_parts`（时辰不详→时柱为 null） |

**Rationale**: 前端零后端改动即可读取；缺时柱、藏干缺失等边界已能在数据层识别。
**Alternatives considered**: 后端新增「关系图 JSON」字段——否决，违背"无后端改动"范围，且生克关系是标准规则，前端可轻易推导。

## 6. 可访问性：箭头颜色 + 文字双编码

**Decision**: 流通箭头同时用颜色（绿/红/灰）与文字（「生/克/比」）标注（clarify 已确认，spec FR-006 / SC-008）。文字为单一汉字，不引入图标/符号。
**Rationale**: 红绿色盲（约占男性 8%）无法仅凭颜色区分相生/相克；文字标注成本极低且让测试断言不再依赖颜色。
**Alternatives considered**: 仅颜色（视觉最简）、颜色+线型（实线/虚线）——均已向用户呈现，用户选择颜色+文字。

## 7. 视觉呈现方式（已确认）

**Decision**:
- **干支双层箭头**：天干层、地支层各自连接相邻柱，按生/克/比着色并标注（clarify 确认）。
- **藏干折叠可点开**：主图只显示天干十神 + 宫位标注 + 地支五行色块；藏干默认隐藏，点击柱节点展开该柱藏干十神，同一时刻至多一柱展开（clarify 确认）。
- 四柱节点横向排列；日主（日干）高亮；窄屏（≥360px）等比缩放或横向滚动（spec SC-007）。

**Rationale**: 与用户确认的交互一致；主图信息密度适中，藏干按需展开，兼顾"易看"与"完整"。

## 8. 技术实现约束（为 tasks 提供依据）

- 纯前端，新增 `components/RelationDiagram.vue` + `utils/relations.ts`，不改 `types.ts`。
- 不新增运行时依赖：五行色复用 `utils/wuxing.ts` 的 `WX_COLOR`/`wxColor`；图示用 CSS + 少量 SVG（箭头线/标签）即可，Vant 仅用于卡片容器（可选）。
- 遵循既有组件风格：`wx-card` 卡片、scoped style、`--wx-*` CSS 变量（参照 ChartDisplay / PillarTable）。
- 测试：`relations.spec.ts`（纯函数：关系判定/宫位/图例/藏干整理）+ `RelationDiagram.spec.ts`（组件渲染）+ `ChartResult.spec.ts` 追加卡片断言。
