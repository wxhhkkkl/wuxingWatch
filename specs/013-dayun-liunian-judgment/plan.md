# Implementation Plan: 岁运判定（大运与流年加入后的推导）

**Branch**: `013-dayun-liunian-judgment` | **Date**: 2026-09-21 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/013-dayun-liunian-judgment/spec.md`

## Summary

把「大运」「流年」真正接入判定，按**三阶段**逐级累积：**原局 → 加入大运 → 加入流年**，每阶段**各成一页**。技术上有三条主线：

1. **状态层**：把「月令」从唯一的状态来源扩展为「**月令 + 大运的综合（折中）状态**」——这是书中岁运介入时所有「化神是否当令」判据的判据（书 上 907-953），而现有实现的所有条件② 只看原局月令。折中**只取月令与大运，流年不参与**（书 上 3213）。
2. **参与层**：岁运之支/干作为**真正的参与者**进入关系层与生克层——与原局任何一柱均相邻（书 上 578）、参与刑冲合害并受让位约束、能与原局相隔之支形成「桥接」使其变为可作用（书 上 1541、下 1684）、适用位置分档（临月令/临大运/临流年的各自度数档）。
3. **呈现层**：三个页面层层递进，两个新页面的结论**并列罗列两个阶段**的判断，**引擎不合成吉凶**；结论**不落库**，按需实时计算。

**原局路径必须逐项零回归**（FR-023/SC-003）——这是本期的硬约束，也是设计上的主要张力来源。

## Technical Context

**Language/Version**: Python 3.12（后端）/ TypeScript 5 + Vue 3（前端）
**Primary Dependencies**: 既有 FastAPI、SQLAlchemy、lunar-python、Vue 3 + Vant + Pinia、Vitest；**无新增依赖**（宪法 I）
**Storage**: MySQL（`bazi_chart.chart_result` 为 JSON 文本列）。**本期不新增任何持久化**——岁运推导结论按需实时计算（FR-026）；原局结论的保存与「口径变更则重算」路径一字不改
**Testing**: pytest（`cd backend && uv run pytest tests`，`testpaths=["tests"]`、`pythonpath=["src"]`）+ Vitest（`cd frontend && npx vitest run`）；另加**书中岁运算例清单对拍**（复用 012 期已入库的 `fixtures/book-cases.json` 与 `scripts/compare_wangdu.py`，非 pytest 断言、产出差异清单）
**Target Platform**: 移动端 Web（Vant）+ 后端 Linux/Windows 通用
**Project Type**: web-application（backend/ + frontend/）
**Performance Goals**: 纯函数、单命例毫秒级。**切换大运步/年份须即时响应**——这是页面的核心交互；流年按需单年计算（不预计算整步 10 年），基准为单命例一次完整判定（关系→旺度→格局→取用）的耗时
**Constraints**:
- 宪法 II：TDD 红-绿-重构，失败测试先行
- **FR-023 / SC-003：原局结论改动前后逐项一致**（含既有记录打开后）——原局路径不得被岁运改造污染。这是**硬门**
- **FR-017 / SC-004：阶段独立性**——移除流年后逐项回到大运页的值；移除大运后逐项回到原局页的值
- **FR-003 / FR-017a：折中只取月令与大运**，流年绝不参与折中（书自己的口径，非简化）
- FR-016a：**引擎不合成吉凶**——无吉凶档位、无事件断语
- FR-005：岁运之支与原局**任何一柱**均相邻，不受柱距限制
- FR-013：大运干支**十年一体**，无「前五年干/后五年支」分割
- 无新增数据持久化；两个新页面须可从**新排盘**与**已保存记录**两处进入

**Scale/Scope**: 9 SC / 4 用户故事 / **36 FR**。后端约 4 个模块受影响（relations / ban / tables / dayun）+ 生克层与 pipeline 的两处接线；前端新增 2 个页面 + 路由 + 1 处本地判定副本的处置；既有测试基线 1181 passed / 9 failed（9 红为 012 遗留，须保持恒等）

## 实现要点（供 tasks.md 细化）

**A. 状态层（折中状态接线）**——影响面最大，须先做
- 把「当前步大运」做成关系层的**隐式上下文**（与既有 `_MONTH_CTX`/`_REL_CTX`/`_SELF_CTX` 同构），不改函数签名
- 接进所有「化神是否当令」的判据：`relations._hua_ok` 条件②、`_muku_chong_ok` 条件②、`_zixing_ok` 条件②、`_ju_dangzhong_ok`、四库土局
- 折中算法复用 `tables.compromise_state`（书 上 907-953 已实现且有测试），只缺调用方
- **流年不进折中**（FR-003/FR-017a）——须有专门测试守住，因为流年确实进了关系层，最易误接
- 书 上 943/953 的「月令/大运被改变时的两段折中」与 上 1050-1088 的墓库月令综合状态表须一并接

**B. 参与层（岁运支/干作为一支）**
- **相邻性**：`_adjacent`/`_touching` 已有伪列豁免（正确，书 上 578）；但 `_ju_runs`/`_contiguous` **没有**，导致岁运支的相邻性靠下标巧合——须按「岁运与任何柱相邻」的显式语义改写（现状证据：书 上 3502 的大运补成三合**实测不复现**）
- **桥接**：岁运介入使原局相隔之支「变为可作用」（书 上 1541、下 1684、上 2203/2944/3502）；须区分生克与相合（FR-008）
- **位置分档**：六冲的临月令/临大运档已在 `ban._chong_pen`；**补「临流年」只在书明写的三处**（四墓库藏干 上 399-403/449-451/491-497、未克申酉 上 2309、辰戌丑未冲 下 1735-1752），六冲**不外推**流年档（FR-009）
- **天干层面**：`stem_he.py:26` 现明文排除大运/流年之干，须纳入（FR-012/FR-014a）；「岁运之干不与原局之干争合」沿用既有澄清
- **运支藏干入池**：书 上 884/900/901（「未本身藏丁火 3 度」）——现 `pipeline` 的 cols 只含四柱

**C. 生克层与 pipeline**
- 岁运之支/干进入生克结算（现只进关系层）
- **阶段独立性**（FR-017）：pipeline 须能产出「阶段 2」与「阶段 3」两份结论，且**阶段 3 中的阶段 2 部分与单独跑阶段 2 逐项相同**——实现上以「阶段 2 算一次、阶段 3 在其结果上增量」保证，而非两次独立算
- **原局零回归**：原局路径（不传岁运）**不进入任何新增分支**

**D. 呈现层**
- 两条新路由 + 两个新页面；结论按来源阶段三元标注（属原局/属大运/属流年）
- 「加入流年」页并列罗列两阶段同名判断，**不给吉凶结论**
- 两页可从新排盘结果页与已保存记录详情页进入；从记录进入须当场重推大运与流年
- **命盘图的岁运维度改为只消费后端产出**（已确认事项①）——阶段 2 取 `strength.dayun[]`、阶段 3 取新端点；前端的流年本地判定副本退役，其自建列序（大运,流年,年,月,日,时）与后端相反的问题一并消失。**原局部分的关系判定副本是否同步退役不在本期范围**

**E. 验收基础设施**
- 复用 `fixtures/book-cases.json`（394 例，逐例含大运与书中结论）与 `scripts/compare_wangdu.py`
- 须补齐：**岁运算例清单**（从 394 例中筛出含岁运者，单列一致/差异，差异须能从依据解释——SC-001）
- 须补齐：**原局零回归基准**（改动前一批命盘的原局结论快照，逐项比对——SC-003）

## Complexity Tracking
